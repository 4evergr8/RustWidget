# RustWidget

Windows 桌面挂件：在鼠标旁边挂一只会摆动的小精灵，跟随系统光标状态自动切换动作。

## 特性

- **两种显示模式**
  - 挂件模式：用绳子从光标垂下，带单摆物理
  - 停靠模式：固定在光标旁的指定位置，不摆不晃
- **Verlet 绳链**：绳子会弯曲、会下垂，上下抖动鼠标时末端会跟着反应（参数共振也会自然出现）
- **光标状态联动**：17 种系统光标状态映射到 7 组素材，缺哪组就回落到「正常选择」
- **1:1 像素采样**：纹理按最终显示尺寸生成，GPU 不做二次缩放
- **设置界面**：分组布局、原生数值上下按钮、实时应用
- **锁屏恢复**：锁屏解锁后自动重启进程恢复画面（详见「已知限制」）
- **托盘图标 + 全局热键**

## 环境要求

| 项 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 x64 |
| Rust | 1.82+（MSVC toolchain） |
| Windows SDK | 需要 `rc.exe`，用于把图标嵌进 exe |

## 构建

```bash
cargo build --release
```

产物：`target/release/rustwidget.exe`

`build.rs` 在构建时做两件事：

1. 嵌入 `app.manifest`（启用 comctl32 v6 现代控件外观 + per-monitor v2 DPI 感知）
2. 在 Windows SDK 里找最新的 `x64/rc.exe`，编译 `assets/icon.rc` 并链接进 exe

找不到 `rc.exe` 只会打一条 warning，图标不嵌入，其余功能不受影响。

## 运行

exe 同级目录需要：

```
rustwidget.exe
widget.toml          # 可缺省，缺失时用默认值并在首次应用设置时生成
skin/
└── 大肥鱼冬装/       # 皮肤名，对应 widget.toml 里的 skin
    ├── 正常选择/
    ├── 文本选择/
    └── ...
```

```
└── src/
    ├── main.rs           主循环、窗口创建、窗口消息
    ├── config.rs         配置读写、窗口尺寸计算
    ├── cursor.rs         光标状态检测（17 种）
    ├── physics.rs        Verlet 绳链 + 枢轴加速度估计
    ├── render.rs         D3D11 + DirectComposition 渲染

    ├── sprite.rs         素材加载、缩放、预乘 alpha

    └── icon.rs           从 exe 资源加载图标
```

## 素材格式

每个状态一个目录，目录里放该状态的序列帧：

- 格式：`.png`（大小写不敏感），按**文件名排序**播放
- 同一目录内的帧尺寸建议一致（不一致时按最大外框统一缩放）
- 加载时按**最长边**缩放到 `display_size`，另一边等比，不拉伸
- 先预乘 alpha 再缩放（顺序反了会在边缘出现暗边）
- 目录不存在 → 自动回落到「正常选择」

## 配置项

`widget.toml` 是扁平 `key = value` 格式，设置界面会整份重写它（注释会丢）。

| 字段 | 默认值 | 说明 |
|---|---|---|
| `mode` | `"pendant"` | `pendant` 挂件 / `dock` 停靠 |
| `skin` | `"大肥鱼冬装"` | 皮肤目录名 |
| `display_size` | `96` | 精灵**最长边**的显示像素，纹理按此生成 |
| `frame_ms` | `100` | 每帧停留毫秒，决定动画播放速度 |
| `rope_length` | `60` | 绳长（px），仅挂件模式 |
| `gravity` | `2400` | 重力加速度（px/s²） |
| `damping` | `2.2` | 阻尼，越大越黏；超过 5 基本不摆 |
| `max_angle_deg` | `35` | 最大摆角，同时决定窗口宽度 |
| `cursor_clearance` | `18` | 窗口顶边相对光标下移的像素，**必须 > 0** |
| `dock_x` | `18` | 停靠模式横向偏移 |
| `dock_y` | `18` | 停靠模式纵向偏移 |
| `poll_ms` | `8` | 空闲时主循环休眠间隔，越小跟随越跟手 |
| `physics_hz` | `240` | 物理积分频率，固定步长 = 1/该值 |

### 几个参数的经验值

- **阻尼**：`1~2` 有明显摆动手感，`5` 以上几乎不动，`20` 是完全过阻尼
- **最大摆角**：`35~50` 画面紧凑；`80` 会甩到接近水平，窗口会撑得很宽
- **光标间隙**：设成 `0` 时光标热点会落在窗口内，点击可能被窗口吃掉（`HTTRANSPARENT` 跨进程不可靠）

## 实现要点

**渲染**：D3D11 + DirectComposition，窗口用 `WS_EX_NOREDIRECTIONBITMAP` 做真透明。精灵和绳子都是带纹理的四边形/三角带，预乘 alpha 混合。

**物理**：绳子是 12 个质点的 Verlet 链，每步 4 次距离约束迭代。窗口跟着光标平移，所以在窗口坐标系里给每个质点加 `-a` 的惯性力，`a` 由临界阻尼弹簧跟踪器（≈6.4Hz）估计——直接对鼠标坐标做二阶差分噪声太大。

**固定步长**：物理用 1/`physics_hz` 秒的固定步长加累加器推进，和渲染帧率解耦。有 `.min(0.1)` 和 `steps < 24` 两个保护，防止卡顿后补步过多形成死亡螺旋。

**锁屏恢复**：锁屏会污染进程内的 GPU/合成状态——实测连「销毁并重建窗口 + 重建交换链」都救不回来，只有新进程能恢复。所以收到 `WM_WTSSESSION_CHANGE` 的解锁事件后直接重启自身。

## 已知限制

- **锁屏解锁靠重启进程**，会有约 2 秒空档、托盘图标闪一下。这是目前唯一验证有效的方案。
- **光标采样受渲染节流**：有动画时循环被 `Present` 的 vsync 卡在约 60Hz，把 `poll_ms` 调到 1 也不会有提升。
- **`cursor_clearance` 必须为正**，否则窗口会挡住光标所在位置的点击。
- **图标缓存**：换了 exe 图标后资源管理器可能仍显示旧图标，按 F5 或移动文件刷新。
- **无单实例保护**：重复双击会启动多个挂件。
